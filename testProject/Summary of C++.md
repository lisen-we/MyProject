1. Debug 程序可以加载 Release 动态库，但这不代表可以安全地在两者之间传递 Qt/STL 等复杂 C++ 对象。如果 DLL 接口只传递 C ABI 数据，例如整数、POD 结构、字节缓冲区和字符串，并且内存始终由创建它的模块负责释放，Debug/Release DLL 通常可以混用。
   如果对象是在 Debug 主程序中创建的，例如 `QVector<QString>`、`QDomElement` 或其他 Qt/C++对象，然后将其指针传入 Release DLL，由 Release DLL按照自己的 Qt/CRT 配置访问、复制、修改引用计数或释放，就可能产生 ABI和堆管理不一致。强制转换只是掩盖了类型边界，并不是错误的直接原因。
2. 内存破坏可能发生在 DLL 接口执行期间，但直到返回 Debug 程序、局部对象析构或下一次堆操作时，才由堆管理器检测出来，并报错：`Invalid address specified to RtlValidateHeap`。因此，跨 Debug/Release DLL 边界时应避免传递 `QString`、`QVector`、`QDomElement`、STL 容器等复杂对象。更安全的方式是传递 UTF-8 JSON或字节数据，并保证“谁申请，谁释放”。
3. 在VS中已经打开项目的情况下点击创建新的项目可能会继承原来项目的解决方案，导致附加目录不准确，此时需要删掉解决方案再重新打开，这样会生成一个新的解决方案
4. QMap内部是通过有序树来实现的，所以把一个容器作为key的情况下需要提供容器之间的比较函数，或者改而使用QHash来进行实现。
5. 空的类也可以实例化，每个实例回占用最小的内存（通常是一个字节），因为编译器必须要为每个对象分配一个独特的地址，所以sizeof(A)也是1；
6. 子类在继承父类的时候不能够继承父类的构造函数、析构函数、赋值运算符、拷贝构造函数、私有成员函数
7. 当一个子类继承多个父类的时候，其初始化列表的顺序决定基类的初始化顺序，但是其成员变量会按照在类中的生命顺序进行初始化，而不是按照在初始化列表中的顺序，其构造函数主体会最后执行。
8. 构造函数的类型有：默认构造函数、参数化构造函数、拷贝构造函数、移动构造函数、委托构造函数、显示构造函数。其中显示构造函数explicit限定词的作用是防止隐式类型转换和复制初始化。
9. 全局变量和局部变量的区别在于作用范围、生命周期、存储位置、初始化值不同，前者存储在数据段，默认为零值，后者通常存储在栈上，默认为未定义值
10. 常量指针（const int* ptr) 指针指向的数据不能被修改，但是指针本身可以指向另一个地址
      指针常量（int* const ptr) 指针本身的地址不能被修改，但是其指向的值可以被修改
11. 智能指针的缺点：更多的性能开销；循环引用导致的内存泄露（`shared_ptr` 只有在引用计数变成 `0` 时，才会释放对象；循环引用会让对象互相“续命”，导致引用计数永远无法变成 `0`）；代码复杂性增加
12. 智能指针的引用计数是线程安全的（智能指针可以被赋值给不同线程中的指针）
      智能指针管理的对象并不是线程安全的（在不同的线程中修改智能指针管理的对象会存在数据竞争）
      智能指针管理对象的读写操作需要额外的同步机制来保证线程安全
      shared_ptr适用于多线程共享同一对象的场景
13. 智能指针和裸指针的使用场景有所区别：智能指针常常使用在需要自动管理资源生命周期、防止内存泄露、管理复杂对象的所有权以及生命周期的场景；裸指针常使用在简单的、临时的、不设计所有权的对象，适用于性能开销高以及不需要管理资源生命周期的场景。
14. shared_ptr可能会导致循环引用从而引发内存泄露，但是weak_ptr可以打破循环引用，防止内存泄露（weak_ptr仅提供对于资源的弱引用，不控制生命周期，也不增加引用计数）`weak_ptr` 必须从 `shared_ptr` 构造。
15. 使用引用作为函数参数的优势：对于大对象，引用的传递效率更高；可以避免空指针问题，提高代码安全性。
16. 模板的实例化时机：编译时进行实例化（调用函数模板或者创建模板类实例的时候，编译器会生成对应代码）
17. 模板类一般把声明和定义都放在头文件中，是因为模板在实例化时，编译器必须同时看到模板的完整定义和具体模板参数。每个使用模板的 `.cpp` 文件都是独立编译的，如果模板定义只放在另一个 `.cpp` 文件中，当前编译单元看不到定义，就无法实例化，最终通常产生链接错误。简单来说，`main.cpp` 知道“需要哪个具体版本”，但看不到“如何生成”；`test.cpp` 看得到“如何生成”，但不知道“需要哪个版本”。把模板定义放进头文件，就是让使用模板的编译单元同时知道这两件事。如果想要分开模板定义和实现，也可以显示地告诉编译器需要哪些版本:
       <!-- template void func<int>(int);  template void func<double>(double); -->
18. define、const、static的区别：define的作用域是全局，在编译的时候替换文本，但是不会做静态检查，适合用于定义简单的常量以及宏；const和static能够进行静态的类型检查，具有更高的安全性，const会被存储为编译时常量，static则是静态存储。
19. new和malloc的区别：两者都是在堆上分配内存，但是new会调用构造函数来进行初始化，而malloc则不会调用构造函数，需要手动初始化；new会返回指定类型的指针，而malloc始终返回void*，需要进行强制类型转换；在分配内存失败的时候，new会抛出异常，malloc会返回NULL。
20. heap和stack的区别：前者的内存是动态分配和管理的的，需要程序员控制内存的申请和释放（或者垃圾回收机制自动管理），申请的空间通常较大，用于存储动态分配的对象以及数据，并且可以进行动态拓展，相较于栈的访问速度较慢；后者的内存是自动管理的，函数返回的时候自动释放，申请的空间大小固定，用于存储函数的返回地址、参数和局部变量，由于数据通常位于连续的内存块，所以访问的速度通常较快。栈的管理成本较低，但是可能会遇到栈溢出的问题，对象的生命周期通常伴随着函数的执行开始和结束，在函数结束之后再试图访问该变量会触发未定义行为导致程序崩溃
21. 栈溢出的原因通常是：递归调用过深，分配的局部变量过大，无限递归或者过深的嵌套调用，当栈的空间用尽之后，程序会崩溃。
22. RAII(resource acquisition is initialization) 指的是在对象创建的时候获取资源，在对象析构的时候释放资源，即便异常发生时也可以保证资源被正常释放。
23. 友元函数是类外的函数，在函数内可以使用friend来声明，声明之后可以访问类的私有成员和保护成员；友元类在类的定义中使用friend class来声明，例如在A中声明friend class B，标识B是A的友元类，这样B就可以访问A的私有和保护成员
24. 虚函数的调用不是在编译的时候解析的，而是在运行的时候解析，每个含有虚函数的类都有一个对应的虚函数表（一个函数指针数组，类中有多少个虚函数，这个表中就有多少个元素），对象通过这个表来查找正确的函数调用，虚指针指的是指向虚函数表的指针，每个包含虚函数的对象都会自动包含一个指向其类的虚函数表的指针，多个相同的派生类对象内部的虚指针指向同一张虚函数表（相同派生类对象的虚指针地址不同，但是其保存的值是相同的）。
25. 构造函数不能声明为虚函数（对象在构造的时候还未建立虚函数表）；静态函数不能声明为虚函数（静态函数没有this指针，与对象无关）；内联函数声明为虚函数后，仍保留 `inline` 的语言属性，但通过基类指针或引用进行动态调用时，可能因编译期无法确定具体版本而不能内联展开。
26. 虚函数表在编译阶段创建，在链接阶段分配到具体的全局内存空间，虚指针在运行的时候实例化类对象的时候初始化。
27. 在没有虚函数的情况下，可以通过函数指针、std::function、手动类型擦除和模板来实现多态。
