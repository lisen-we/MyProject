# C++ 知识点总结
---

## 一、DLL、Qt 与开发环境

### 1. Debug 程序与 Release DLL 混用

Debug 程序可以加载 Release 动态库，但这不代表可以安全地在两者之间传递 Qt、STL 等复杂 C++ 对象。

如果 DLL 接口只传递 C ABI 数据，例如整数、POD 结构、字节缓冲区和字符串，并且内存始终由创建它的模块负责释放，那么 Debug/Release DLL 通常可以混用。

如果对象是在 Debug 主程序中创建的，例如 `QVector<QString>`、`QDomElement` 或其他 Qt/C++ 对象，然后将其指针传入 Release DLL，由 Release DLL 按照自己的 Qt/CRT 配置访问、复制、修改引用计数或释放，就可能产生 ABI 和堆管理不一致的问题。

> 强制类型转换只是掩盖了类型边界，并不是错误的直接原因。

### 2. 跨 DLL 边界导致的内存破坏

内存破坏可能发生在 DLL 接口执行期间，但直到返回 Debug 程序、局部对象析构或下一次堆操作时，才由堆管理器检测出来，并报告以下错误：

```text
Invalid address specified to RtlValidateHeap
```

因此，跨 Debug/Release DLL 边界时应避免传递以下复杂对象：

- `QString`
- `QVector`
- `QDomElement`
- STL 容器

更安全的方式是传递 UTF-8 JSON 或字节数据，并遵循“谁申请，谁释放”的原则。

### 3. Visual Studio 解决方案继承问题

在 Visual Studio 已经打开项目的情况下创建新项目，可能会继承原项目的解决方案配置，导致附加目录不准确。

此时可以删除解决方案文件后重新打开项目，让 Visual Studio 生成新的解决方案。

### 4. 使用容器作为 `QMap` 的键

`QMap` 内部通过有序树实现。因此，将一个容器作为键（key）时，需要提供容器之间的比较函数；也可以改用 `QHash` 实现。

## 二、类、对象与变量

### 5. 空类的大小

空类也可以实例化。每个实例会占用最小的内存，通常是一个字节，因为编译器必须为每个对象分配一个独立地址。

```cpp
sizeof(A) == 1;
```

### 6. 子类不会直接继承的成员

子类继承父类时，不能直接继承父类的以下成员：

- 构造函数
- 析构函数
- 赋值运算符
- 拷贝构造函数
- 私有成员函数

### 7. 多继承与成员的初始化顺序

当一个子类继承多个父类时：

1. 基类按照它们在派生类声明中的出现顺序初始化。
2. 成员变量按照它们在类中的声明顺序初始化，而不是初始化列表中的书写顺序。
3. 构造函数主体最后执行。

### 8. 构造函数的类型

构造函数主要包括：

- 默认构造函数
- 参数化构造函数
- 拷贝构造函数
- 移动构造函数
- 委托构造函数
- 显式构造函数

其中，`explicit` 限定符用于防止不期望的隐式类型转换和复制初始化。

### 9. 全局变量与局部变量

全局变量和局部变量的主要区别如下：

| 对比项 | 全局变量 | 局部变量 |
| --- | --- | --- |
| 作用范围 | 通常为文件、命名空间或程序范围 | 所在代码块或函数范围 |
| 生命周期 | 通常贯穿整个程序运行期 | 通常随代码块或函数执行而开始、结束 |
| 存储位置 | 数据段 | 通常位于栈中 |
| 默认初始化 | 默认进行零初始化 | 未显式初始化时通常为未定义值 |

### 10. 常量指针与指针常量

| 类型 | 写法 | 指针指向的数据 | 指针本身的指向 |
| --- | --- | --- | --- |
| 常量指针 | `const int* ptr` | 不能通过该指针修改 | 可以改变 |
| 指针常量 | `int* const ptr` | 可以修改 | 不能改变 |

## 三、指针、引用与资源管理

### 11. 智能指针的缺点

- 存在额外的性能开销。
- 可能因循环引用导致内存泄漏。
- 可能增加代码复杂度。

`shared_ptr` 只有在引用计数变为 `0` 时才会释放对象。循环引用会让对象互相“续命”，导致引用计数始终无法变为 `0`。

### 12. 智能指针与线程安全

- 智能指针的引用计数操作是线程安全的，智能指针可以被复制给不同线程中的指针。
- 智能指针管理的对象本身不一定是线程安全的。在不同线程中修改该对象可能产生数据竞争。
- 对被管理对象的读写操作，需要额外的同步机制来保证线程安全。
- `shared_ptr` 适用于多线程共享同一对象的场景。

### 13. 智能指针与裸指针的使用场景

| 指针类型 | 适用场景 |
| --- | --- |
| 智能指针 | 自动管理资源生命周期、防止内存泄漏、表达复杂对象的所有权关系 |
| 裸指针 | 简单、临时且不涉及所有权的对象，或对性能开销敏感且无须管理资源生命周期的场景 |

### 14. 使用 `weak_ptr` 打破循环引用

`shared_ptr` 可能因循环引用引发内存泄漏，而 `weak_ptr` 可以打破循环引用。

`weak_ptr` 仅提供对资源的弱引用，不控制资源的生命周期，也不会增加引用计数。`weak_ptr` 必须从 `shared_ptr` 构造。

### 15. 使用引用作为函数参数

使用引用作为函数参数具有以下优势：

- 对于大型对象，引用传递的效率更高。
- 可以避免空指针问题，提高代码安全性。

## 四、模板、宏与内存分配

### 16. 模板的实例化时机

模板在编译时实例化。调用函数模板或创建模板类实例时，编译器会生成对应的代码。

### 17. 模板的声明与定义

模板类通常将声明和定义都放在头文件中，因为模板实例化时，编译器必须同时看到模板的完整定义和具体模板参数。

每个使用模板的 `.cpp` 文件都是独立编译的。如果模板定义只放在另一个 `.cpp` 文件中，当前编译单元看不到定义，就无法完成实例化，最终通常会产生链接错误。

简单来说：

- `main.cpp` 知道“需要哪个具体版本”，但看不到“如何生成”。
- `test.cpp` 看得到“如何生成”，但不知道“需要哪个版本”。

把模板定义放进头文件，可以让使用模板的编译单元同时知道这两件事。如果想分离模板的定义和实现，也可以显式告诉编译器需要实例化哪些版本：

```cpp
template void func<int>(int);
template void func<double>(double);
```

### 18. `#define`、`const` 与 `static`

| 关键字 | 特点 | 常见用途 |
| --- | --- | --- |
| `#define` | 在预处理阶段进行文本替换，不进行类型检查 | 定义宏或简单常量 |
| `const` | 具有类型信息，可参与类型检查 | 定义不可修改的值 |
| `static` | 表示静态存储期、内部链接或类级成员等语义 | 静态变量、静态成员及限制链接范围 |

### 19. `new` 与 `malloc`

| 对比项 | `new` | `malloc` |
| --- | --- | --- |
| 内存分配位置 | 堆 | 堆 |
| 初始化 | 调用构造函数 | 不调用构造函数，需要手动初始化 |
| 返回类型 | 指定类型的指针 | `void*`，在 C++ 中需要显式转换 |
| 分配失败 | 默认抛出异常 | 返回 `NULL` |
| 释放方式 | `delete` / `delete[]` | `free` |

### 20. 堆与栈

| 对比项 | 堆（heap） | 栈（stack） |
| --- | --- | --- |
| 管理方式 | 动态分配，通常由程序员或资源管理对象负责释放 | 自动管理，函数返回时自动释放栈帧 |
| 常见用途 | 动态分配的对象和数据 | 返回地址、参数和局部变量等 |
| 空间大小 | 通常较大，可动态扩展 | 通常较小且存在固定上限 |
| 访问与管理 | 分配和管理成本通常较高 | 管理成本通常较低 |
| 常见风险 | 内存泄漏、悬空指针 | 栈溢出、返回局部对象地址导致未定义行为 |

### 21. 栈溢出的常见原因

- 递归调用过深或无限递归。
- 分配的局部变量过大。
- 函数调用嵌套过深。

当栈空间耗尽时，程序可能会崩溃。

## 五、RAII 与友元

### 22. RAII

RAII（Resource Acquisition Is Initialization，资源获取即初始化）是指：

- 在对象创建时获取资源。
- 在对象析构时释放资源。

即使发生异常，也可以借助对象析构保证资源被正常释放。

### 23. 友元函数与友元类

友元函数是类外函数，可以在类中使用 `friend` 声明。声明后，该函数可以访问类的私有成员和保护成员。

友元类使用 `friend class` 声明。例如，在类 `A` 中声明：

```cpp
friend class B;
```

这表示 `B` 是 `A` 的友元类，因此 `B` 可以访问 `A` 的私有成员和保护成员。

## 六、虚函数、多态与继承

### 24. 虚函数、虚函数表与虚指针

虚函数调用通常在运行时解析。每个含有虚函数的类通常都有一张对应的虚函数表，表中保存虚函数入口。

对象通过虚函数表查找正确的函数调用。虚指针是指向虚函数表的指针，每个包含虚函数的对象通常会包含一个指向所属类虚函数表的虚指针。

多个相同派生类对象中的虚指针字段位于各自对象内，因此地址不同；但其中保存的虚函数表地址通常相同。

### 25. 哪些函数不能声明为虚函数

- **构造函数**不能声明为虚函数，因为对象在构造开始时还不是一个完整的派生类对象。
- **静态成员函数**不能声明为虚函数，因为静态成员函数没有 `this` 指针，与具体对象无关。
- **内联函数**声明为虚函数后仍保留 `inline` 的语言属性；但通过基类指针或引用进行动态调用时，编译器可能无法确定具体版本，因此不一定能内联展开。

### 26. 虚函数表与虚指针的创建时机

- 虚函数表由编译器生成，并由链接器放入最终程序的相应存储区域。
- 虚指针在创建类对象的过程中被初始化。

### 27. 不使用虚函数实现多态

在不使用虚函数的情况下，可以通过以下方式实现多态：

- 函数指针
- `std::function`
- 手动类型擦除
- 模板

函数指针的主要目的是在运行时决定调用哪个函数；手动类型擦除的主要目的是隐藏具体类型或接口，只暴露统一接口。

模板实现的多态属于编译期多态（静态多态），其他方式通常属于运行时多态（动态多态）。

### 28. 虚函数表的存放位置

在 Linux/Unix 系统中，虚函数表通常存放在可执行文件的只读数据段；在 Windows 系统中，通常存放在只读或常量数据区。具体布局属于编译器实现细节。

虚表指针位于对象实例内，其具体位置同样由编译器 ABI 决定。虚表指针通常在对象构造过程中被初始化。

### 29. 纯虚函数与抽象类

纯虚函数用于定义接口。含有纯虚函数的类称为抽象类，不能被直接实例化。

运行时通常通过虚函数表和虚表指针实现动态绑定。

### 30. 虚继承与菱形继承

虚继承解决了菱形继承中共同基类子对象被重复包含的问题。

在虚继承结构中，中间类初始化列表里对虚基类的初始化会被忽略，虚基类由最派生类的构造函数负责初始化。

> **注意：** 菱形继承中的 `B`、`C` 等中间类构造函数仍会正常执行。被忽略的只是它们初始化列表中对虚基类 `A` 的初始化，并不是整个构造函数。

## 七、底层机制与编译流程

### 31. 野指针与悬空指针

- **野指针：** 指向无效或不可预测内存地址的指针，常见原因是指针未初始化便被使用。
- **悬空指针：** 指向已经被释放内存的指针。对象或内存块被释放后，原指针仍保留旧地址，就会成为悬空指针。

释放内存后，应及时更新相关指针；在适用场景中，可以将其置为 `nullptr`。

### 32. 为什么要进行内存对齐

内存对齐主要有以下目的：

1. **提高性能：** 对齐的数据通常允许 CPU 以更少的内存访问周期完成读写。
2. **防止错误：** 某些处理器访问未对齐数据时可能触发硬件异常。
3. **确保兼容性：** ABI（Application Binary Interface，应用二进制接口）会规定数据布局与对齐方式，使数据结构能够在相同 ABI 约定下被正确读写。

在网络通信和文件存储中，不应直接依赖本机结构体的内存布局；通常需要明确序列化格式。

### 33. `extern "C"`

`extern "C"` 允许 C++ 代码按照 C 的链接规范导出或引用函数，主要用于解决 C 与 C++ 之间的符号链接问题。

C 不支持函数重载，编译后的函数符号通常较简单；C++ 支持函数重载，因此编译器通常会对函数名进行名称修饰（name mangling），将参数类型等信息编码到符号名中。

`extern "C"` 相当于告诉 C++ 编译器：按照 C 的链接规范处理该函数，不要使用 C++ 的名称修饰规则。

### 34. C++ 编译流程

```text
源代码
  ↓
预处理：处理宏定义、条件编译、头文件包含等
  ↓
编译：将预处理后的代码转换为汇编代码
  ↓
汇编：将汇编代码转换为目标文件（机器代码）
  ↓
链接：将多个目标文件和库文件链接为可执行文件或动态库
```
